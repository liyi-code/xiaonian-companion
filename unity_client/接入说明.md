# 小念 ⇄ Unity 3D 游戏 接入说明（多 NPC + 任务系统）

把「小念」的大脑（本地 Python：LLM + 视觉理解 + 意识层联想 + 自主动作表情）接入你的 Unity 工程，
让她在 3D 世界里是一个**人形、全身+面部可动**的 NPC，能自己探索、看图、联想、做表情动作，
还能和玩家接任务、推进任务进度。

---

## 一、整体架构

```
┌─────────────── Unity 工程（你已有）───────────────┐         ┌──── Python 端（本仓库 src/）────┐
│  BridgeHub (1个WS连接, 按 npc_id 路由)            │  WS     │  bridge.py (GameBridge)          │
│     ├─ NpcManager → 实例化多个 NPC VRM 预制体      │◄───────►│     ├─ NPCBrain(default/lynn/…)  │
│     │     └─ NpcAgent (对话/表情/动作/语音/任务)   │  JSON   │     │    assistant(每NPC独立大脑)   │
│     │           ├─ AgentController (移动/看/交互)  │          │     │    emotion / tts             │
│     │           └─ SymbolicPerception (符号感知)   │          │     │    world_state (符号世界)     │
│     ├─ QuestSystem (任务UI+进度)                  │          │     │    explorer (意识层驱动探索)   │
│     └─ TaskTrigger (物体→上报任务进度)            │          │     └─ quest.py (任务系统)        │
│  可交互物体挂 PerceptTag + TaskTrigger            │          │  vision.py / clayer/ (视觉/联想) │
└──────────────────────────────────────────────────┘          └─────────────────────────────────┘
```

**关键设计**：每个 NPC 在 Python 端有**完全独立的大脑 + 世界感知 + 任务**（隔离哲学同 multiplayer_memory），
Unity 端每个 NPC 是独立的 VRM 实例 + NpcAgent。所有 NPC 共用一条 WebSocket，消息带 `npc_id` 路由。

## 二、Python 端（已完成，已验证）

运行（先起 Python 桥，再开 Unity）：

## 三、Unity 端接入步骤

### 1. 依赖
- **UniVRM**（VRM0 或 VRM1，导入后可用 `BlendShapeProxy` / VRM 面部）。把你已有的「小念 VRM」导入，
  转成 **Prefab**（拖进场景再拖回 Project 成 prefab）。
- **WebSocketSharp**：把 `WebSocketSharp.cs` 放进 `Assets/`（或 Package Manager 装 `com.detonator.websocket-sharp`）。
- **Newtonsoft.Json**：Unity Package Manager 搜索 `com.unity.nuget.newtonsoft-json` 安装。
- **TextMeshPro**：Unity 自带，用于对话气泡与任务面板。

### 2. 拷贝脚本
把本目录（`unity_client/`）下的这些 `.cs` 全部复制到你的 `Assets/Scripts/Xiaonian/`：
- `BridgeHub.cs` ✅ 新增（连接中枢）
- `NpcManager.cs` ✅ 新增（多 NPC 实例管理）
- `NpcAgent.cs` ✅ 新增（单 NPC 行为）
- `NpcManager` 依赖：`AgentController.cs`（已改，去掉旧依赖）
- `SymbolicPerception.cs`（已改，多 NPC 版）
- `QuestSystem.cs` ✅ 新增（任务 UI）
- `TaskTrigger.cs` ✅ 新增（物体触发）
- `WavUtil.cs` ✅ 新增（wav→AudioClip）
- `PerceptTag.cs`（已有，可交互物体标注）
- `XiaonianBridge.cs` ⚠️ **已废弃，不要挂**，仅作协议参考

### 3. 场景搭建（在你已有工程里）
1. 创建一个空 GameObject `BridgeHub`，挂 `BridgeHub.cs`，Inspector 填 `wsUrl = ws://127.0.0.1:8765`。
2. 同一物体或另一个空物体挂 `NpcManager.cs`，把「小念 VRM 转成的 Prefab」拖进 `npcPrefab` 槽。
3. 创建 UI Canvas：
   - 一个 `TextMeshProUGUI` 做**对话气泡**（放在小念头顶 World Space，或屏幕空间），挂到对应 NpcAgent 的 `bubbleText`。
   - 一个 `TextMeshProUGUI` 做**任务面板**，挂到 `QuestSystem.cs` 的 `questText`。场景里放一个 `QuestSystem` 空物体。
4. 给场景里「小念能感知/交互」的物体挂 `PerceptTag.cs`（填 id/name/type）；需要触发任务的物体再挂 `TaskTrigger.cs`
   （填 `targetNpcId` + `objectId`，`objectId` 要与 `quest.py` 任务模板里的 `objective.target` 一致）。
5. （可选）给小念 VRM 预制体挂一个 `Camera` 作为她的视角（用于低频视觉快照），在 `SymbolicPerception` 的
   `watchCamera` 槽引用它。

### 4. 多 NPC 配置
- **最简单**：让 Python 端 `bridge.py` 预置多个 NPC（改 `GameBridge.__init__` 加 `self.spawn_npc("lynn","Lynn")`）。
  Unity 收到 `ready` 后会自动为每个 NPC 生成一个小念克隆（横向排开）。
- **动态**：Unity 运行时发 `{"type":"spawn_npc","npc_id":"boss","name":"Boss"}` → Python 创建新大脑 →
  下发 `npc_spawned` → Unity `NpcManager` 生成实例。
- 每个小念克隆都是独立大脑、独立记忆、独立任务——互不串台（已 Python 端验证）。

### 5. VRM 面部表情（重要）
`NpcAgent.SetEmotion` 用 **VRM0** 的 `BlendShapeProxy.ImmediatelySetValue(BlendShapeKey)`，预设映射：
`happy/joy → Joy`、`sad/sorrow → Sorrow`、`angry/anger → Anger`、`surprised/surprise → Surprise`、`neutral → Neutral`。
如果你用的是 **VRM1**，请把那段改成 `runtime.Expression.SetWeight(...)`（Unity 顶部已加 `#if UNITY_VRM` 守卫，
编译不会报错，但 VRM1 需自行补一行）。

## 四、任务系统

### Python 端（已写好，`quest.py`）
- 任务模板在 `_QUEST_TEMPLATES`（神社/宝箱/交友三条示例）。
- 触发：① 玩家对话提到「任务/帮忙/找/带我去」→ 派任务；② 探索发现 `type=="quest"` 物体 → 派对应任务。
- 进度：Unity 上报 `quest_event{kind, object_id}` → 匹配 `objective` → 完成 → 下发 `quest_update(state=completed)`。

### Unity 端
- `TaskTrigger` 挂在物体上：玩家进入碰撞体（或点击）自动发 `quest_event`。
  - 宝箱 → `kind=interact, objectId=chest_01`
  - NPC → `kind=talk, objectId=npc_lynn`
  - 区域入口 → `kind=reach, objectId=shrine_north`
- `QuestSystem` 接收 `quest_update` 显示任务列表与勾选进度。

### 自定义任务
编辑 `src/quest.py` 的 `_QUEST_TEMPLATES`，加你自己的任务（title/desc/objectives[kind,target,desc]/reward）。
`objective.target` 必须和 Unity 里 `TaskTrigger.objectId` 完全一致。

## 五、消息协议（速查）

**下行 Python→Unity**（均带 `npc_id`）：
| type | 字段 | 含义 |
|------|------|------|
| `ready` | `npcs:[{npc_id,name,voice_ready}]` | 连接就绪 + NPC 列表 |
| `token` | `text` | 流式对话字 |
| `emotion` | `dominant` | 主导情绪 → 表情 |
| `action` | `name` | 动作名 → Animator 触发器 |
| `speech_start` | — | 开始说话 |
| `audio` | `wav`(base64) | 语音 wav 字节 |
| `talk_stop` | — | 结束说话 |
| `agent_command` | `action,target,pos` | 探索：移动/看/交互/踱步 |
| `agent_thought` | `thought` | 调试：想法 |
| `quest_update` | `quest_id,title,desc,state,objectives[],reward` | 任务状态 |
| `npc_spawned` / `npc_despawned` | `npc_id` | NPC 生命周期 |

**上行 Unity→Python**（均带 `npc_id`）：
| type | 字段 | 含义 |
|------|------|------|
| `user_input` | `text` | 玩家对话 |
| `world_load` | `region_id,loaded` | 区域加载/卸载 |
| `symbolic_percept` | `agent_pos,objects[]` | 符号感知（无图） |
| `visual_snapshot` | `cam_pos,image_b64` | 低频视觉快照（base64 jpg） |
| `quest_event` | `kind,object_id,npc_id_from` | 任务进度上报 |
| `spawn_npc` / `despawn_npc` | `npc_id,name` | 动态 NPC 生命周期 |

## 六、运行流程
1. 启动 Python 桥：`启动桥_多NPC.bat`（端口 8765）。
2. Unity 打开你的工程，进入场景，运行（Play）。
3. `BridgeHub` 自动连接 → 收到 `ready` → `NpcManager` 生成小念（及预置的其它 NPC）。
4. 走近小念，UI 输入框打字回车 → 流式出字 + 出声 + 表情动作。
5. 小念在玩家不交互时会**自己探索**（explorer 驱动：走向有意思物体、看、交互、踱步），
   低频截图给视觉 API「结合符号感知」推理，回写意识层联想。
6. 触发任务：对话说「给我个任务」或走到 `type=quest` 物体 → 任务面板出现 → 完成目标 → 进度勾选。

## 七、注意事项 / 已知限制
- **视觉 API**：`vision.py` 需要 `VISION_ENABLED=true` + `VISION_API_KEY`（智谱 GLM-4V 等）。不配则视觉快照降级跳过，符号感知仍工作。
- **语音**：`tts` 未就绪时（没配语音后端）只会出文字+表情+动作，不会出声——这是预期降级。
- **VRM1**：面部表情代码需自行补 `Expression.SetWeight`（见上文）。
- **LLM 延迟**：首次对话若模型冷加载（本地 Ollama）可能慢几秒，属正常；任务触发是规则判定、不依赖 LLM 回复，瞬时生效。
- **无法本地编译**：本仓库只提供 C# 源码，需在你本机 Unity Editor 编译验证（已尽量按 Unity API 严格书写）。
