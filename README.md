# 小念 · 本地版（AI 挚友桌面程序）

一个**完全可本地离线运行**的 AI 挚友桌面程序（Windows）。基于本地大模型 [Ollama](https://ollama.com)，
支持 Live2D 形象、语音、屏幕陪伴、长期记忆与自主行为。你的聊天记录、记忆、模型全部留在自己电脑上，
不上传任何云端（除非你主动配置云端模型）。

> 这是「本地版」：默认用本机 Ollama 跑模型，开箱即用、隐私可控。仓库已自带可商用的 Live2D 模型
> **桃濑日和 / hiyori_pro**。语音默认关闭，可自选开启。

## 🚀 快速开始（本地 Ollama）

1. **安装并启动 Ollama**，拉取一个对话模型（推荐，约 9GB）：
   ```bash
   ollama pull qwen2.5:14b
   ```
   > 备选：`deepseek-r1:32b`（更强但更慢更吃显存）、`qwen2.5:7b`（轻量）。
   > 想让模型常驻内存、避免反复冷加载，可设系统环境变量 `OLLAMA_KEEP_ALIVE=-1`（重启 Ollama 生效）。

2. **安装 Python 3.10+**（含 pip，已加入 PATH）。

3. **获取本仓库**：
   ```bash
   git clone https://github.com/liyi-code/xiaonian-companion.git
   cd xiaonian-companion
   ```

4. **双击 `启动.bat`**：
   - 首次运行自动创建 `venv` 虚拟环境并安装依赖；
   - 若没有 `.env`，会自动从 `.env.example` 复制一份（已默认指向本地 Ollama）。

5. **（可选）确认 `.env` 里的对话模型指向本地 Ollama**（默认已是，无需改）：
   ```ini
   OPENAI_API_KEY=ollama
   OPENAI_BASE_URL=http://localhost:11434/v1
   MODEL=qwen2.5:14b
   ```
   > 也可以启动后点输入条上的 `◐` → 「API 设置」里填，还能“测试连接”。

6. **再次双击 `启动.bat`** 即可开始聊天。

> ⏳ 首次发消息前，小念会冷加载本地模型，约需十几秒到一两分钟（取决于模型大小与显卡）。
> 加载期间输入条会提示“模型加载中”。加载完成后常驻内存，之后秒回。

## 🧠 意识层（clayer）架构

小念的「脑子」不是只靠 qwen 一句话生成。我们在 qwen **外挂了一层「意识层」**（`src/clayer/`）：它**不改模型权重、不微调、不量化**，而是作为认知框架，在「输入侧（联想引导）+ 解码侧（logit_bias 硬偏置）」两头调制 qwen，模拟人脑的联想、注意力、遗忘与价值判断。这样既保留 qwen 的语言能力，又让回复带上「小念自己在想事情」的连续意识流。

> 说明：本仓库默认模型是 **`qwen2.5:14b`**（非 13b）。「改版」指的是在 qwen 之上叠加意识层，而非改动权重。

### 它怎么「改」qwen（两条接入点）

1. **提示词软引导**：每次对话前跑一次意识活动，把当前并联浮现的多道「意念」（主念 / 副念 + 情绪 + 价值导向）拼成【潜意识联想场】段，塞进 system prompt，让 qwen 自然带上这层联想倾向。
2. **解码硬偏置（关键）**：意识层算出的概念选取概率 `P(c)` 被编译成 `logit_bias = GAIN · P(c)^γ`，注入 qwen 的 `logit_bias` 参数 —— 被「链式解锁」唤醒的联想概念，其 token 在每一步 softmax 里被直接抬高，严格正相关。主念额外 boost，用户输入里已有的种子词不偏置（模型本来就看得见）。
3. **动态逐段偏置**：长回复切成 ~48 token 一段，每生成一段就重跑一次意识活动，用模型刚说的话当新种子，边说边更新偏置 + 采样温度，模拟「边说边想」。

### 一次意识活动的流程

```
感知(显著度加权) → 种子带初始能量(=感知权重+历史显著度)
   → 沿关联链多跳扩散激活(≤4 跳、能量衰减、阈值截断、匹配度门控)
   → 权重经 softmax 成概率(基础概率 0.02 防独裁 / 上限 0.55 防僵化)
   → 最多 4 道并行「意念」互相抑制生成、按 vigor(强度+匹配+唤醒+价值)竞争注意力(主念胜出)
   → 熵映射到 qwen 的温度 / top_p
```

### 模块组成（`src/clayer/`）

| 模块 | 职责 |
|------|------|
| `consciousness.py` | 总编排：`think()`（感知→激活→解锁→概率→多念竞争→组装引导）、`learn()`（统计回写）、`consolidate_memory()`（睡眠压缩） |
| `assoc_graph.py` | 关联图：扩散激活、Jaccard 相似度、强度维度、遗忘衰减、`consolidate()` 弱词并入强词 |
| `probability.py` | 概率引擎：分布构建 / 伪随机组合 / 温度与熵调制 |
| `token_bias.py` | 把概率分布编译成 `logit_bias`，直接介入 qwen 每步解码 |
| `memory_store.py` | 概念计数、显著度、容量淘汰 |
| `perception.py` | 分词（优先 jieba，无则退回 CJK 单字 + bigram） |
| `affect.py` | 情绪（效价-唤醒二维）+ 注意力 softmax 分配 |
| `sleep.py` | 双通路睡眠引擎：通路二「创新组合」（合成概念 + slope_utility 边际效用 + 弱连接 + 想象力出口） |
| `cl_config.py` | 全部常量，且**每项都带神经科学文献出处**（见下） |
| `_core.py` | 统一入口：优先 C++ 加速库 `pyclayer.pyd`，失败自动回退纯 Python |

### 底层「判断标准」（元目标）

意识层内置 `WELLBEING` 价值词库：命中「成长 / 健康 / 早睡 / 自律 / 陪伴…」得正价值分，命中「熬夜 / 拖延 / 摆烂 / 内耗…」得负分。价值分作为竞争力第四轴，使输出天然偏向「让使用者的生活越来越好」——即使某个念事件再强、情绪再躁，只要它在拉低生活品质，就会被压下去。这与性格情感系统、受约束自主权限共用同一套健康底线。

### 性能自愈（治「越聊越慢」）

记忆图遍历耗时超过阈值时触发睡眠状态机：

- `≥ 450ms` → **犯困态**：自动向用户表达“好累、想睡”，仍正常对话；
- `≥ 500ms` → **强制睡眠**：停止输出并 `consolidate()` 把快归零的弱词并入其最强相关词；
- 压缩后仍超阈值 → 进入「用户筛选存储」模式（备份另存 / 清空 / 筛选另存）。

另有**近因强度衰减**（冷门概念自然遗忘）与**全局节点封顶（≤60000）**双保险，防止图无限膨胀、爆内存或变成「意大利面」。

### 工程亮点

- **C++ 加速 + 纯 Python 回退**：启动时做数值 parity 自检（容差 1e-9），不一致自动降级；C++ 后端释放 GIL 让多念真并行，Python 回退保证「换机器、没编译也能跑」。
- **常量有科学依据**：储存量 42000（成人平均词元量，Brysbaert 2016）、注意力焦点 4±1（Cowan 2001）、语义网小世界平均路径 3–4 跳（Steyvers & Tenenbaum 2005）、平均关联度 ≈13、情绪 positivity offset（Diener）等。
- **持久化**：`brain_state/mind.json` 随对话长期积累个人「记忆」；`learn_async()` 与 TTS 播放重叠，不阻塞对话回合。

## 💭 双通路睡眠与想象力出口

小念「睡着」时，不再只做单一的语义压缩，而是**两条通路并行**处理当天的记忆：

- **通路一：语义压缩** —— 复用 `consolidate()`，把快归零的弱词并入最强相关词，降低遍历耗时（治“越聊越慢”）。
- **通路二：创新组合** —— 把当前**高权重概念**（强度 ≥ 阈值）随机两两碰撞，生成**合成概念**，新权重 = 成员权重之和，存进独立索引（`combos.json`）。

两类压缩产物**可以相互关联**（合成概念之间 / 合成概念与原概念之间建立双向弱连接）。当小念在**表层思索不出答案**（扩散激活无候选念）时，会回查合成概念索引作为**想象力出口**，把睡眠时碰撞出的灵感交给 LLM「换个角度想」。

### 边际效用（slope_utility）—— 驯化而非预测

每个合成概念记录**最近 N 次被使用时用户/自身状态的斜率变化**（不是绝对值）。小念用了某个组合后：
- 自己更开心/平静（joy+calm ↑）→ 效用为正 → 保留并强化；
- 更难过/不安/生气（anger/sadness/anxiety ↑）→ 效用为负 → 下次检索直接丢弃。

于是「越来越有用」的组合被自然保留，「有害」的组合被自然淘汰——这是**驯化**，不是靠预测。

### 安全边界

- 合成概念存**独立索引**，不写进主关联图 `AssocGraph`，不破坏 C++/Python 数值 parity；
- 总开关 `DUAL_PATHWAY_ENABLED=False` 即可**一键回退**到旧版（只跑通路一），行为完全不变；
- 起步保守：组合阈值 0.8、每次只做二元组合、单次上限 12 个（`cl_config.py` 可调），跑一周看日志再逐步放宽。

## 💞 性格与情感如何驱动动作

小念不是“一套固定动作循环”。她的肢体风格由**情绪（情感）× 性格**两层实时融合决定：

- **情绪（5 维：joy/anger/sadness/calm/anxiety）**：`joy`（兴奋度）直接调制动作快慢与大小——开心时挥手更快更大，低落时更慢更小。
- **性格（5 种：温柔平静 / 活泼开心 / 傲娇小脾气 / 敏感爱哭 / 黏人紧张）**：由情绪长期累计差值派生，决定**动作风格**而非内容：

| 性格 | 动作风格 | 身体倾向（lean） | 招牌小动作（micro） |
|---|---|---|---|
| 活泼开心 | 轻快、幅度大 | 略前倾 | 爱挥手 |
| 黏人紧张 | 中等速度、略小幅 | 明显前倾（靠近） | 倾向跟随/靠近 |
| 傲娇小脾气 | 略快、小幅甩动 | 后缩（别过脸） | 偶尔转身 |
| 敏感爱哭 | 最慢、最小幅 | 明显后缩、低头 | — |
| 温柔平静 | 舒缓、克制 | 中性略后 | — |

**数据流（端到端）**：

```
对话/事件 → emotion.motion_params()  [emotion.py]
   = 当前性格的 {speed_mul, amplitude_mul, lean, micro}
→ bridge.compute_action_params(brain)  [bridge.py]
   = 融合 joy×性格 → {speed, amplitude, lean, trait, micro}
→ WebSocket action 事件（带 trait/lean 字段）
→ NpcBridgeClient.cs 转发
→ ConceptStateMachine.TriggerAction(name, dur, speed, amp, trait, lean)
   = 把 lean 折算进骨骼（上臂前举 / 上身前倾），micro 影响普通聊天兜底动作
→ Unity 角色演出带“性格”的肢体语言
```

> 性格只改**演出风格**，永远不改变底层目的（让使用者生活越来越好，健康护栏不变）。
